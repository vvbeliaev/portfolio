# Ярусы репозитория и модель хранения знания

Сессия целиком ушла на структуру, а не на продукт. Два вопроса, оба решены.

## Вопрос первый: где живут эксперименты

Исходная мысль владельца — вести прототипы cogisoft прямо здесь, пока проект не
созреет отделиться. Проверка показала, что репозиторий **уже** двухбрендовый:
`apps/vvbeliaev` и `apps/cogisoft` деплоятся каждый своим workflow, а расходились
только документы, описывавшие репу как «личный бренд: сайт, блог, резюме».

Уточнение по ходу разговора изменило рамку: сюда идёт **только собственное R&D**.
Клиентские проекты получают свои приватные репозитории, инфраструктура — отдельный
приватный `vvbeliaev/infra` вне кластера, cogisoft со временем уезжает на свой
GitLab (нужен контроль доступов при найме людей). Публичность по умолчанию тогда
безопасна по построению, а не по бдительности.

**Решение — три яруса по жизненному циклу:**

- `apps/<name>` — деплоится: Dockerfile, workflow с `paths:`, Coolify-app, домен.
- `labs/<name>` — эксперимент: папка и README со статусом, больше ничего. Вне
  pnpm-глобов, чтобы `git subtree split` давал работающий проект без починки.
- `workspace/` — не-код: тексты, ассеты, стратегия, резюме.

Граница `labs` / `workspace` — **код против не-кода**, не «сырое против готового».
Повышение `labs → apps` — тот же ритуал, что уже есть у статей: осознанный
перенос, а не смена флага. Понижение разрешено явно.

**Рассмотрено и отвергнуто:** один ярус `projects/*` с режимом из метаданных
(дерево перестаёт отвечать, что здесь живое — а ради контекста агента всё и
затевалось) и деление по доменам `apps/tools/labs/pkgs` (каждый новый предмет
требует классификации без пользы).

`pkgs/*` убран из воркспейса: слот был объявлен ещё в июльской спеке лендинга как
«вне скоупа», за два месяца не получил ни одного жителя. Вернётся, когда появится
второй реальный потребитель общего кода.

## Python: общий uv-воркспейс с аварийным выходом

Корневой `pyproject.toml`, `members = ["labs/*"]`, один `uv.lock`. Виртуальный
корень без `[project]` работает — проверено живым `uv lock` на uv 0.11.28.

Плата известна и записана прямо в файле: воркспейс держит одно разрешение
зависимостей и одно пересечённое `requires-python`, а документация uv прямо
говорит, что для конфликтующих требований воркспейс не годится. Для ML-лаба это
не гипотетика (пин torch под CUDA). Отсюда `exclude` — не костыль, а
проектное решение: лаб с конфликтом уходит туда и лочится сам.

Первым жителем яруса стал `labs/social-kit` — генератор соцкита, до этого лежавший
в `workspace/assets/social/`. Вывод перенаправлен обратно на полку ассетов; SVG
после переезда побайтово те же.

## Вопрос второй: как хранить знание без дублей

Разбор начался с наблюдения, что документы разъезжаются с кодом. Нашлось
предметно: `DESIGN.md` дублирует все 15 значений из `:root` прозой, а четвёртая
копия палитры — в генераторе соцкита — **уже разошлась**: `#8b90a4` против
`#7d8294` там, где оба называются «приглушённый». При том что README соцкита
предписывает брать цвета только из `DESIGN.md`.

Отсюда модель, которая теперь лежит в корневом `CLAUDE.md`: у знания есть **род**
(факт / норма / обоснование / намерение) и **триггер** (всегда / по пути / по
вызову / по событию). Дубль возникает ровно тогда, когда одно утверждение лежит
под двумя триггерами. Критерий выживания документа: отвечает ли он на вопрос,
ответ на который нельзя получить чтением кода.

**Следствия, реализованные в тот же день:**

- `CLAUDE.md` — императив для агента, `README.md` — описание для человека и
  GitHub. Файлы, где это смешивалось (`labs/README.md`, `workspace/README.md`),
  разделены надвое.
- Конвенции статей переехали в `.claude/rules/blog.md` с `paths:`. До этого они
  жили в `workspace/README.md`, то есть **не грузились никогда** — самый дорогой
  из найденных пробелов. Правило по пути выбрано вместо скила сознательно: скил
  срабатывает по суждению модели о своём описании и может промахнуться, правило
  срабатывает по факту чтения файла и промахнуться не может.
- `docs/` становится журналом: файл на решение, датированный, только дописываемый.
  Три спеки схлопнуты в записи и удалены — намерение после воплощения либо
  умирает, либо превращается в обоснование.
- `docs/export-ramp.md`, написанный в этой же сессии, удалён владельцем как
  лишняя формализация. Процедура выноса — три команды git, они не заслуживают
  документа.

## Прочее той же сессии

Гвард в CI получил третью джобу: у каждого лаба README со статусом, и
`uv lock --check`. Прогон `git subtree split -P apps/cogisoft` вхолостую
подтвердил, что cogisoft вырезается целиком (8 коммитов, полное дерево) —
единственный долг перед реальным отъездом в том, что его `DESIGN.md` наследует
от корневого через `parent:`.

Из корня убраны два случайных PNG-мока — репозиторий профильный, корень витрина.
