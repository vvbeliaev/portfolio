# CV под вакансию

Резюме здесь не пишется с нуля и не редактируется по месту. Оно **собирается как
отражение** одного источника правды под конкретную вакансию.

## Источник правды

`workspace/private/backbone.yaml` — настоящая биография с датами, метриками и
контекстом. Разделы: `identity`, `narrative`, `disposition`, `experience`,
`projects`, `education`, `awards`, `skills`. Пункты помечены тегами
`roles: [ai-fullstack, analyst, devops, tpm, data-engineer, ...]` — это и есть
готовая разметка под роли.

**Жёсткие правила:**

- **Ничего, чего нет в backbone.** Не додумывать достижения, не округлять
  метрики, не переносить формулировки из текста вакансии в опыт. Если нужного
  факта нет — сказать владельцу, а не сочинить.
- Не хватает факта, но он был — сначала дописать в backbone, потом собирать.
  Правка идёт в корень, не в отражение.
- **Ничего из `private/` в публичные пути.** В backbone телефон и контакты; PDF
  с ними в `apps/*/public/` не кладём (см. `workspace/CLAUDE.md`).

## Процедура

1. **Прочитать вакансию** — что за роль, какие требования названы явно, какой
   язык (RU/EN). Если вакансии на руках нет, спросить текст или ссылку.
2. **Выбрать тег роли.** Совпал с существующим (`ai-fullstack`, `analyst`,
   `devops`, `tpm`, `data-engineer`) — берём его. Не совпал — не заводить новый
   молча, а предложить владельцу.
3. **Отобрать пункты** по тегу, затем отранжировать под конкретные требования
   вакансии: наверх то, что она называет явно. Отбор и порядок — решение, ради
   которого этот шаг делает агент, а не скрипт.
4. **Собрать отражение** в формате rxresume: `basics` (name, headline, email,
   phone, telegram, location, url, customFields), `sections` (summary, experience,
   projects, education, awards, skills, languages, interests), `metadata`.
   Ориентир — соседние файлы в `workspace/private/cv/reflections/`.
5. **Сохранить** как `workspace/private/cv/reflections/<lang>-<slug>.json`, где
   slug — роль или компания. Существующее отражение не перезаписывать без
   спроса: оно могло быть уже отправлено.
6. **Рендер по запросу.** JSON → rxresume.me вручную владельцем. Либо путь в
   обход: свёрстанный `workspace/private/cv/html/<lang>-<slug>.html`
   (print-A4, self-contained) → headless Chrome `--print-to-pdf` → `cv/pdf/`.

## После сборки

Публичные поверхности не меняются: сайт и профильный README — отдельный,
осознанно суженный срез. Если в резюме всплыл проект, которого нет на сайте, это
**отдельное решение владельца**, а не следствие сборки. Появится на сайте —
получит `backboneId` и попадёт под `uv run labs/backbone-check/check.py`.
